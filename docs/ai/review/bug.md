# Bug 审查规则

本阶段检查 PR 是否引入能够导致崩溃、错误结果、资源泄漏、并发故障或安全边界破坏的具体 bug。
开始分析前必须继续读取 `docs/ai/review/common.md`。

## 阶段边界

本阶段关注“代码在某条可达路径上会发生什么错误”，
不负责泛泛的代码风格、命名偏好或没有运行时影响的结构建议。

以下问题优先在本阶段报告：

- panic、越界、溢出、除零或无效解引用；
- 返回错误数据、遗漏更新、错误对象或破坏数据一致性；
- 文件、内存、锁、引用计数、PID、IRQ 等资源泄漏；
- 数据竞争、死锁、丢失唤醒或错误的同步可见性；
- 错误被吞掉后继续执行，导致状态被当作成功提交；
- 输入验证缺失导致越权、越界访问或内核状态破坏。

纯控制流可读性、API 形态和规范问题分别交给 Logic 或 Guidelines 阶段。

## 强制工作流

1. 调用 `get_annotated_diff`，列出所有行为变化点。
2. 对每个可能影响运行时行为的文件使用 `read_file` 阅读完整上下文。
3. 搜索被修改函数、类型、trait 和字段的所有关键调用方。
4. 沿正常路径、错误路径和清理路径分别检查状态变化。
5. 对并发代码建立最小事件顺序，确认锁、原子变量、唤醒和销毁的先后关系。
6. 对资源类对象追踪“获取 — 发布 — 失败回滚 — Drop”四条路径。
7. 只输出能够构造触发条件并落到 diff 行的 finding。

## 重点检查项

### 1. Panic 与非法访问

检查新增或修改的：

- `.unwrap()`、`.expect()`、`panic!()`、`todo!()` 和 `unreachable!()`；
- 数组、slice、Vec 和字符串索引；
- `first/last/get` 返回值被错误假设为存在；
- 除法、取模、位移和对齐计算中的零值或超范围值；
- 空集合、零长度缓冲区和缺失配置下的路径。

不要看到 `unwrap` 就直接评论。
必须确认失败值能由真实调用方、外部输入或合法系统状态产生。

### 2. 整数与大小计算

内核代码中重点追踪：

- 地址加减、页数和字节数换算；
- `usize`、`isize`、ABI 整数和窄整数之间的转换；
- `len * size_of::<T>()`、区间终点和向上取整；
- signed/unsigned 混用以及负 errno 转换；
- release 模式下可能静默回绕的普通算术。

验证溢出后是否可能缩小校验范围、分配过小缓冲区或访问错误地址。

### 3. 错误处理与回滚

对每个新增 `Result` / `Option` 处理检查：

- 错误是否被 `let _ =`、`.ok()`、默认值或空分支吞掉；
- 部分状态更新后失败，是否恢复旧状态；
- 底层 errno 是否被错误映射；
- 清理失败是否会遗留仍可见的半初始化对象；
- 日志记录后继续执行是否真的安全；
- retry 是否可能无限循环或重复提交非幂等操作。

区分“有意 best effort”与“误把失败当成功”。
前者需要上下文、注释或 API 契约证明。

### 4. 资源生命周期

追踪以下资源的所有权：

- heap 分配、页、frame、映射和 DMA 缓冲区；
- 文件描述符、inode/dentry 引用、socket 和设备句柄；
- task、PID/TID、wait queue、timer 和 work item；
- IRQ 注册、MMIO 映射、设备资源和平台状态；
- 锁 guard、禁中断状态、preempt 状态和 CPU-local guard。

检查 early return、`?`、panic、重复注册和对象 Drop 时是否对称释放。
同时检查重复释放、释放后使用和发布顺序错误。

### 5. 并发与时序

遇到锁、原子变量、wait/wake、RCU 风格生命周期或跨 CPU 状态时，检查：

- 是否存在锁顺序反转；
- 持锁期间是否调用可能阻塞、调度或回调外部代码的操作；
- 条件检查与状态更新之间是否存在 TOCTOU；
- 唤醒是否可能发生在 waiter 可见之前；
- 原子 Ordering 是否足以发布和观察关联数据；
- 对象是否可能在另一个 CPU 仍引用时销毁；
- 中断上下文与进程上下文是否访问同一状态但使用不兼容的锁。

报告时应描述至少两条参与路径及形成故障的事件顺序。

### 6. 边界与外部输入

对 syscall、设备输入、文件系统数据、网络包、配置和启动参数检查：

- 长度、范围、标志位和枚举值是否在使用前验证；
- 用户指针是否只通过项目的用户内存抽象访问；
- 验证后的值是否在使用前被替换或失效；
- 部分 copy、短读写和 fault 是否被正确处理；
- 不可信索引是否能选择越权对象或错误 namespace 中的资源。

## 高信号示例

可以报告：调用方允许空 slice，而新增代码直接访问 `slice[0]`。

不应报告：仅因为函数接收 slice 就假设它可能为空，
但所有入口都已通过类型或显式校验保证非空。

可以报告：错误路径在全局表插入对象后返回，且没有 Drop 或显式移除。

不应报告：只看到 `Arc::clone()` 就声称引用泄漏，
没有追踪克隆值的所有权和释放路径。

## 输出要求

遵循 `common.md` 的 finding JSON 格式。
正文必须包含具体触发条件和实际后果，不能只写“可能 panic”“可能死锁”。
如果没有满足证据门槛的问题，输出 `未发现问题`。
