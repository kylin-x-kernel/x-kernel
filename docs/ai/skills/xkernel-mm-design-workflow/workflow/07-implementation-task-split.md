# Phase 7: Implementation Task Split

## Owner

Design Arbiter with input from X-Kernel Memory Designer

## Purpose

Split the frozen design into implementable tasks without writing code.

## Required Output

Use `templates/implementation-task-split-template.md`.

## Rules

- Task splits must follow the frozen design only.
- No code snippets beyond pseudocode-level signatures if absolutely needed.
- Each task should name prerequisites and validation targets.
- Each task must map to a target crate and to the structures/interfaces named
  in the frozen design.

## Exit Criteria

The resulting task list is staged, dependency-aware, and aligned with phase-1 scope.
