# CG-008-unsafe-attribute-safety: Justify unsafe symbol and entry attributes

- **Rule**: Do not treat `#[unsafe(naked)]`, `#[unsafe(no_mangle)]`, or linker-section placement as self-justifying. Each use of `#[unsafe(naked)]`, `#[unsafe(no_mangle)]`, or `#[unsafe(export_name = ..)]` MUST have a nearby `// SAFETY:` justification.
- **Scope**: The lint checks the three listed attributes on parsed source items, including associated and foreign items and loaded out-of-line modules. `link_section` is outside this first scope. It sees parsed items even when `#[cfg]` later removes them, but the contents of a cfg-disabled out-of-line module are not loaded or checked. It does not expand attributes nested inside `cfg_attr`. Items generated by `macro_rules!` or procedural macros are not visited; put the justification at the attribute in the macro source and review each use. Crates outside the selected build configuration are not checked.
- **Why**: These attributes promise externally visible symbol identity or a special entry contract that Rust cannot verify. A local explanation lets reviewers check the actual ABI, symbol ownership, and machine state.
- **How to check**:
  1. Find the first attribute in the contiguous group containing the unsafe attribute, whether outer or inner. A `// SAFETY:` comment must be directly above that group, with no blank line or unrelated code between it and the group. A multi-line `// SAFETY:` comment is accepted.
  2. One comment covers all three in-scope unsafe attributes in that group. A comment after an attribute does not cover an earlier attribute.
  3. The lint checks presence only. Review must check whether the justification names the real entry-state assumptions as required by `docs/ai/skills/code-guidelines/unsafety.md:425-427`. For `no_mangle` and `export_name`, explain why the symbol is unique and matches its assembly, linker, compiler, or C ABI consumer, including ABI and signature. For `naked`, explain the entry state used by the assembly and why its body is only assembly.
- **Exceptions**: Use the paired Dylint exception attributes from
  [README.md](README.md#suppressing-a-check). Suppress a generated or externally constrained case only on the smallest enclosing item with `#[allow(unknown_lints, undocumented_unsafe_attribute, reason = "CG-008-unsafe-attribute-safety: <why a local comment cannot document this attribute>")]`. For an item inside an `extern` block, place the allow on the block; early lint levels are not applied to individual foreign items. A reason must explain the actual constraint; convenience is not an exception.
- **Counter-example**:

```rust
#[unsafe(no_mangle)]
pub extern "C" fn firmware_entry() {}
```

- **Example**:

```rust
// SAFETY: The firmware calls the unique `firmware_entry` symbol using the C ABI
// with no arguments; this signature matches that entry contract.
#[unsafe(no_mangle)]
pub extern "C" fn firmware_entry() {}
```

- **Run**: `make dylint` scans the configured kernel; `make dylint_test` runs the lint's UI tests. Details: `tools/lints/README.md`.
