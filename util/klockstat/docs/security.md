# klockstat — Security and Reliability Analysis

## Overview

`klockstat` is an append-only diagnostic module: it adds atomic counters on existing lock paths without changing lock semantics.
The main risks are information exposure, statistical accuracy, and the `unsafe` registry access boundary.

## Host Test Scope

Host test fixtures in `tests/host/lib.rs` and `tests/host/runtime.rs`
remain private children of their original source modules. They require
`cfg(test)`, with the runtime fixture additionally gated by `stats`.
Moving them changes no production API, registration lifetime, unsafe boundary,
or feature selection, and introduces no guest test runtime dependency.

## Trust Model

```
User-space reader (/proc/lock_stat)
        │
        │ read-only text
        v
┌─────────────────────────────┐
│  dump_lock_stat / snapshot  │
└─────────────────────────────┘
        │
        │ Relaxed atomic read
        v
┌─────────────────────────────┐
│  LockClassStats (per class)  │ <── kernel lock fast path writes
└─────────────────────────────┘
```

- **Lock implementations (ksync/kspin)** trust `LockClassStats::record_*` to be a side-effect-free counter.
- **Userspace readers** can only obtain aggregated statistics and cannot modify kernel state through this interface.

## External Boundaries / Attack Surface

| Boundary | Description | Risk |
|------|------|------|
| `/proc/lock_stat` | Exposes text to processes that have procfs access | Leaks kernel source file paths (`file:line`), helping to locate the kernel layout |
| The statistics counters themselves | Can be observed indirectly through side channels (read latency) | Low; similar to ordinary performance counters |

This module:

- **does not access user memory directly**;
- **does not parse user input** (the output is fixed-format text generated by the kernel);
- **does not change lock acquisition order or wakeup semantics**.

When `KFEAT_LOCK_STAT` is enabled, the threat model should record that the `location` field exposes the
source path strings compiled into the image.

## Unsafe Inventory

| Location | Operation | Invariant |
|------|------|--------|
| Runtime publication | No local unsafe code | `klazy::Once` owns initialization and release/acquire publication; published slots are immutable except atomic counters |

The `linkme` distributed slice is collected by the linker script via `KEEP`, and relies on the build system
correctly retaining the `LOCK_CLASSES` section.

## Thread Safety

- `LockClassStats` counters are `AtomicU64`; concurrent `record_*` from multiple CPUs is safe.
- Runtime slots are initialized once and never recycled. Snapshots use
  nonblocking reads and do not hold a registration lock while allocating.
- Snapshots use `Relaxed` loads and tolerate slight tearing (acceptable for diagnostics).

## Failure and Abuse Scenarios

| Scenario | Impact | Mitigation |
|------|------|------|
| procfs node still mounted when `KFEAT_LOCK_STAT` is off | Old behavior: an empty table misleads | The node is now gated by the `procfs/lock_stat` feature |
| More than 1024 runtime classes | Statistics become permanently disabled | Fixed storage, no OOM or failure of the underlying lock; dump reports disabled state |
| Misuse of `static Mutex::new` (stats on) | Compilation fails | Documentation requires `static_lock!` |
| Counts do not exactly match real contention | Hotspots misjudged | `design.md` states the metric semantics explicitly |

## Recommendations

- Disable `KFEAT_LOCK_STAT` by default in production images.
- Restrict procfs mount and read permissions (reuse the existing procfs access control).
- Registration supports task and ordinary IRQ contexts but not NMI context.
  An IRQ-save guard prevents same-CPU interrupt/preemption reentry into a
  partially initialized slot; initializers neither allocate nor call out.
- Disabling statistics is diagnostic degradation, not a synchronization failure.
  Existing classes stay alive and frozen counters remain readable; already
  in-flight records may complete. Reporting still uses ordinary `Vec`/`String`
  allocation and is not globally OOM-safe.
- Host tests cover capacity exhaustion, kind separation, stable references,
  concurrent duplicate registration and runtime label formatting. They do not
  execute hardware IRQ masking or prove NMI safety.
